# Связный расширенный обзор — 6 октября 2026

Обычный короткий отчёт, кнопка «Расширенный обзор», веса и исходные оценки
сохранены. Новая версия представления: `extended_review_20261006_v1`.
Переключение `legacy`/`shadow`, сравнение А/Б и тренажёр не изменены.

## Реализация

- `unified/extended_review.py`: локальный слой фактов, реплик и источников;
  материалам, каналу, сроку отправки и следующему контакту соответствуют разные
  факты. Каждый имеет ID реплик, говорящего, тип подтверждения и уверенность.
  В кэше сохраняются диапазоны исходного текста для диагностики.
- Отправка материалов не означает покупку и не подтверждает новый звонок.
  Противоречивые оценки продолжения проверяются по связанным репликам.
  Неустранимое расхождение превращается в одну неопределённость.
- Цитаты проверяются по непрерывной последовательности слов с нормализацией
  пробелов, регистра и типографики. Числа, проценты и знак суммы не подменяются.
  Вывод об отсутствии проверяет весь доступный разговор, а не случайную цитату.
- Отсутствие подтверждённой полноты расшифровки ограничивает отрицательные
  выводы доступным фрагментом. Старым записям полнота не приписывается задним
  числом. Явное `configuration.transcript_complete=true` позволяет проверку
  полного разговора; источника этого признака в исторических снимках обычно нет.
- Доля реплик не объявляется долей времени речи. Старый балл остаётся исходным;
  если его основания сомнительны, обзор говорит, почему нужна проверка.
  Расчёт баллов новых анализов этим изменением не затронут.
- `unified/render.py`: обзор вызывает единый синтез вместо трёх выгрузок.
  Формат короткого сообщения не изменён.
- `unified/store.py`, `unified/overview_cache.py`: версия текста и факты
  кэшируются в существующем поле `expanded`. Прежний текст сохраняется в
  `legacy_text`; первичные анализы, цитаты, версии и исходы не меняются.
  Миграции и дополнительный запрос к модели не нужны.
- `unified/ui.py`: секции отправляются целиком, по лимиту UTF-16, либо файлом.
  Доставка каждого фрагмента фиксируется до/после отправки. Повтор после
  известного отказа продолжает недоставленную часть; неизвестный исход не
  повторяется вслепую. После завершения повторный клик указывает на уже
  отправленный обзор с кнопкой «Показать обзор здесь» и ответом на его первое
  сообщение, если оно ещё доступно. Явное повторное открытие использует
  сохранённый текст и отдельную последовательную версию доставки; повторный
  клик той же кнопки не запускает ещё одну отправку. Старые квитанции и
  сообщения сохранены. Кнопка закрытия удаляет только зарегистрированные
  сообщения обзора текущего получателя; затем можно открыть его заново.
  Неизвестная или незавершённая доставка не сбрасывается при повторном открытии.
- `Actor`, клиент, менеджер и личный чат проверяются прежними функциями;
  пользователь берётся из `callback.from_user`. Callback подтверждается первым.
- Исходная таблица критериев остаётся в сохранённых анализах для диагностики;
  отдельная пользовательская кнопка критериев не добавлялась.

## Проверки

Итоговый профильный запуск: 89 тестов прошли с фиктивными внешними сервисами.
Проверена применимость полного патча к исходной точке: восстановленные из
патча файлы побайтно совпадают с подготовленной реализацией.
Полный discover не завершён: один существующий тест голосового тренажёра
зависает в асинхронном цикле в этой среде (остальные 30 тестов
меню прошли); PostgreSQL-тесты без изолированной БД пропускаются.
Производственные права и доставка не объявляются проверенными этими моделями.

`tests/test_extended_review.py` использует вымышленные разговоры, фиктивный
Telegram и транзакционную модель хранилища с блокировкой. Проверены связки
реплик, расхождения, частичные данные, сроки двух разных действий,
производственная причина, цитаты, применимость, сохранённый балл, старый кэш,
права, двойной клик, ошибка генерации, рестарт с сохранёнными квитанциями,
частичная доставка, закрытие и длинная атомарная секция.

Обновлены ожидания в `tests/test_unified.py` и
`tests/test_report_reanalysis.py`: три самостоятельные выгрузки больше не
являются требуемым поведением.

Контрольный текст: `Extended_review_control_fragment.txt`, генератор
`scripts/build_extended_review_demo.py`. Использованы только четыре точные
реплики из задания. Производственные сложности и отсрочка отмечены отдельно
как описание примера, без вымышленной цитаты. Номер клиента и сохранённый балл
неизвестны. Полная запись и стабильный ID из БД не получены.

## Точка отката и ограничения среды

Исходный commit: `c4f5f76e0beddd8f69068110737f8258e27fb820`.
Копии пяти изменяемых файлов и `rollback.json` сохранены до изменений в
`/opt/callbot-astra/docs/.rollback/extended-review-20261006T162948Z`.

В этой сессии `.git` защищён от записи: fetch, новая ветка, commit и push
недоступны. `.env` недоступен для чтения, соединение с производственной БД
не установлено. Управление systemd отклонено средой. Поэтому изменения
подготовлены в файлах проекта, но внедрение и работа нового обзора в живом
боте не подтверждены. Массовых разборов, транскрибации, сообщений сотрудникам
и изменений производственных данных не было.

После восстановления доступа нужны проверка контрольного звонка по полному
тексту и метаданным, проверки с изолированным PostgreSQL, сохранение в приватной
ветке и перезапуск только основной службы `callbot-astra.service` с проверкой
старта и журналов. Остальные три службы не требуют перезапуска для этого UI.

Для возврата реализации подготовлен `scripts/rollback_extended_review.py`.
Без флага `--apply` он только показывает число новых производных кэшей.
С `--apply` архивирует такие кэши в закрытый файл в папке копии, возвращает
старый текст или очищает отсутствующий старый кэш, затем восстанавливает
пять исходных файлов. Это предотвращает чтение JSON-конверта старым UI.
Исходные баллы, расшифровки и результаты методик не меняются. `--restart`
перезапускает только основной бот. Скрипт в производстве не запускался.

```bash
.venv/bin/python -m scripts.rollback_extended_review /opt/callbot-astra/docs/.rollback/extended-review-20261006T162948Z --apply --restart
```

Копия также сохранена в `/tmp`; постоянная копия указана выше.
Новые модули можно оставить: старая реализация их
не импортирует. Схема БД не менялась. Текущий контроллер отката исходной
методики также сохранён; он не использует производный новый обзор.

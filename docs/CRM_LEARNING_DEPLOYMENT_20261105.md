## Состав и применение

`scripts/package_crm_learning.py <новая-папка>` собирает пакет из чистой
зафиксированной рабочей копии, производной от `2a11936`:

- инкрементальный Git bundle всей согласованной цепочки обучения/читаемости;
- обратный patch для отката;
- список прежних отслеживаемых файлов для резервирования;
- метаданные ревизий и контрольные суммы;
- `deploy.sh` с отдельными режимами `check`, `apply`, `rollback`.

История и файлы до исходной ревизии не дублируются в bundle. Реальные настройки,
`.env`, `webphone.json`, звонки, транскрипты, БД, логи, зависимости и архивы
резервных копий в пакет не включаются. Все каталоги пакета имеют права 700,
архив и служебные файлы — 600. Скрипт исполняется с правами 700.

На сервере через обычный SSH:

```bash
bash /tmp/<имя-пакета>/deploy.sh check
bash /tmp/<имя-пакета>/deploy.sh
```

`check` проверяет hostname, исходный HEAD, чистоту отслеживаемых файлов,
контрольные суммы, bundle и доступность правильной службы. Ничего не меняет.
`apply` повторяет проверки, блокирует параллельный запуск, сохраняет
затрагиваемые прежние исходники в `.deployments/`, импортирует локальный bundle
и делает только fast-forward текущей ветки. Чужие правки и конфликтующие
неотслеживаемые файлы не перезаписываются. Настройки и БД не трогаются.

После этого перезапускается **только `callbot-crm.service`**. Проверяются процесс,
ответ сайта, байты семи статических ресурсов и наличие нового маршрута
`/api/learning/context` (допустим отказ без авторизации). Дополнительно выполняется
публичный HTTPS GET без учётных данных. Сетевой сбой внешнего HTTPS сообщается
отдельно от успешного локального обновления. Caddy и четыре службы Telegram
не перезапускаются; `crm_setup.sh update` не вызывается, поскольку он выполняет
лишние миграции и перезапуски.

## Откат и ошибки

При неуспешном перезапуске или локальной проверке выполняется автоматический
откат к прежним файлам новым Git-коммитом, затем перезапуск только CRM.
История не переписывается; reset/force-push не используются.

Явный откат установленного пакета:

```bash
bash /tmp/<имя-пакета>/deploy.sh rollback
```

Если HEAD или отслеживаемые файлы после выкладки изменились, откат останавливается
для проверки вместо перезаписи новых правок. При незавершённом откате состояние
пишется как `rollback-needs-review`; сообщение об успешной выкладке не печатается.
Резервная копия содержит только прежние исходники; БД и конфигурация не менялись,
поэтому их откат не нужен. Состояние попытки сохраняется в закрытой `.deployments/`.

## Проверки

Работа приложения: ранее пройдено 51 тест Python и 71 сценарий JS,
`CRM_LEARNING_SMOOTH_CHECKS_20261105.json`. Медиа и код приложения при подготовке

Процедура выкладки: `python -B -m unittest tests.test_crm_deploy -v`.
Девять проверок используют реальные временные Git-репозитории, инкрементальные
bundle, архивы и patch; systemd/HTTP заменены явными фиктивными исполняемыми
файлами. Проверены успешная выкладка, перезапуск только CRM, права чтения новых
исходников, source-backup без секретных файлов, отказ systemd до изменения кода,
другой сервер/новый HEAD, чужие правки, неотслеживаемый конфликт, повреждённый
пакет, автоматический откат при плохом ресурсе/ошибке рестарта и ручной откат.
Это не запуск на рабочей службе. Браузерная приёмка остаётся недоступной
(Chromium/Playwright отсутствует).

# Учебная учётка в обычных вкладках AveronCRM

> Подсказки активных шагов переработаны в общую плавающую карточку. Текущее поведение, проверки и ограничения скриншотов: [CRM_LEARNING_FLOATING.md](CRM_LEARNING_FLOATING.md).

Снимок: 4 ноября 2026. Рабочая копия `/tmp/averon-crm-learning-20261104`,
ветка `feat/crm-learning-tabs`; база — `5da8daf` (предыдущая версия обучения).
Подготовлено к ревью, в рабочую CRM не внедрено. Миграций и изменений настроек нет.

## Решение пользователя

Учебные примеры находятся в обычных вкладках CRM. «Обучение» выбирает урок,
показывает задания, выделяет нужный блок и проверяет результат. Данные локальны.
Каждый новый вход начинает чистую ситуацию. Это заменяет прежнюю отдельную
страницу упражнений в iframe; архивная реализация не является текущим интерфейсом.

## Как пользоваться

1. В CRM: «Ещё → Обучение → Войти в учебную учётку» либо «Начать урок в учебной
   учётке». Дополнительный пароль не нужен: компания, роль и модули проверяются
   существующим серверным Viewer.
2. Видны обычные меню, страницы и формы CRM. Верхняя плашка явно сообщает, что
   вход учебный и все записи вымышленные. Менеджеру доступна его программа,
   директору — директорская; клиентский кабинет не получает обучение.
3. Выберите урок. Откроется его обычная вкладка: например, «Очередь» или «Сделки».
   Подсказка показывает «Что сделать», выделяет блок рамкой, не нажимает кнопки.
   «Рабочая ситуация» разворачивается отдельно, объяснение можно пропустить.
4. Выполните действие. Неверные клиент, итог, срок, менеджер или ответ не
   засчитываются. Вопросы по прочитанному задаются в панели подсказки; кнопка
   «Проверить ответ» проверяет содержание, а не просто переводит на следующий шаг.
5. После завершения вернитесь к программе. Есть статусы, счётчик выполненных
   уроков, продолжение и подтверждаемый повтор с чистыми данными данного урока.
6. Крестик приостанавливает урок, убирает карточку и подсветку. Чтобы
   продолжить, откройте «Обучение → Продолжить». В «Попробовать самому» переход «Далее →» доступен после проверки действия;
   в «Показать, где нажать» можно пройти показ без сохранения записей.
7. «Выйти из учебной учётки» возвращает к обычному входу CRM. Следующее
   «Войти в учебную учётку» создаёт новый набор примеров и нулевой прогресс.

Обновление страницы не считается новым входом: оно сохраняет шаг, учебные
изменения и черновики в той же вкладке браузера. После закрытия вкладки данные
могут исчезнуть (sessionStorage). Это локальная учебная программа, не общая
статистика или защищённая аттестация сотрудников. Новая сессия обычного входа
CRM также меняет учебный идентификатор; пароль/токен в браузер не передаются.

При открытой карточке сначала закройте её крестиком и затем переходите в другой
раздел. Подсказка плавает рядом с элементом и не нажимает
крестик за сотрудника, чтобы не терять несохранённые поля.

## Карта и выполненные проверки

Все результаты ниже — запуск настоящего JS-кода обычных страниц в Node с явной
DOM/event-моделью, не настоящий браузер. Для каждой практики выполнена правильная
и ошибочная попытка; неверные ответы на контрольные вопросы также отклоняются.

| Урок | Где открыть в учебной учётке | Что проверяется | Результат |
|---|---|---|---|
| М1 | Обучение → М1 → Очередь | Правильный клиент, немедленное сохранение «Не взял трубку», история; «Отказ» не принимается | Пройден в DOM-модели |
| М2 | Обучение → М2 → Очередь → Перезвоны | Дата/время/комментарий, перенос той же задачи, исходный срок, отсутствие дубля | Пройден в DOM-модели |
| М3 | Обучение → М3 → Сделки | Нужная сделка, «Заметка», следующий шаг в истории | Пройден в DOM-модели |
| М4 | Обучение → М4 → Сделки → Договоры | Сделка, вымышленные реквизиты, локальный документ, связанная запись журнала | Пройден в DOM-модели |
| М5 | Обучение → М5 → Звонки → Отчёты | Разговор, период, подтверждённый вывод, личный отчёт по дате | Пройден в DOM-модели |
| Д1 | Обучение → Д1 → Сводка | Период и менеджер в существующих переключателях, показатель | Пройден в DOM-модели |
| Д2 | Обучение → Д2 → Звонки | Менеджер, период, разговор, вывод | Пройден в DOM-модели |
| Д3 | Обучение → Д3 → Перезвоны | Менеджер, просроченная задача, клиент, исходная дата/время, история; без переноса/закрытия | Пройден в DOM-модели |
| Д4 | Обучение → Д4 → Сделки | «Зависшие», сделка, этап, последнее событие, «Не зафиксирован» | Пройден в DOM-модели |
| Д5 | Обучение → Д5 → Отчёты → Сотрудники | Неделя отчёта, сотрудник, подтверждающий пример разговора | Пройден в DOM-модели |
| Д6 | Обучение → Д6 | Сотрудники, настройки/доступы, доступные автоматизации/робот; только навигация | Пройден в DOM-модели, также без дополнительных модулей |

Названия не придуманы: у сводки менеджер выбирается переключателем, у журнала и
перезвонов — выпадающим списком. У отчётов нет фильтра дат: выбирается датированный
отчёт. Следующий шаг сделки фиксируется «Заметкой». У задачи «Позвонить» открывает
карточку; настоящая кнопка набора в учебной учётке отключена.

В М4 используется штатная форма генератора. В учебном режиме её кнопка называется
«Сформировать учебный договор»: результат виден на странице и в локальном журнале,
без скачивания, рабочего номера и DaData. В рабочем режиме прежняя кнопка
«Скачать договор (.docx)» и её механизм сохранены. Создание не означает отправку.

## Изоляция и устройство

- `crm/learning.py`, `crm/web.py`: GET-вход, HTML обычной CRM и выход из учебной
  учётки. Сервер проверяет пользователя/компанию/роль/модули, отдаёт только учебный
  каталог и безопасный контекст; никакой выгрузки рабочих клиентов/звонков нет.
- `/learning/enter` обновляет HttpOnly/SameSite cookie-маркер входа и перенаправляет
  на `/learning/workspace`. Идентификатор для браузерного хранилища производный,
  не даёт права доступа. Reload сохраняет его, новый вход меняет.
- В HTML контекст — экранированный JSON без исполняемого inline JS. До `app.js`
  загружаются engine, `workspace-model.js` и `workspace.js`.
- `workspace-model.js` реализует локальные ответы API для тех же форм и списков.
  Состояние/данные/черновики/прогресс разделены по входу, компании и роли в
  sessionStorage. У каждого урока свой набор примеров; повтор не стирает другие.
- `app.js` в `/learning/workspace` направляет все api-вызовы в локальный обработчик.
  Старый `review.js`, использующий fetch напрямую, получает локальный ответ из
  bootstrap-перехватчика. Неизвестный запрос отклоняется, рабочего fallback нет.
- CSP всего учебного документа: `connect-src 'none'`, `form-action 'none'`,
  `frame-src 'none'`, `media-src 'none'`, `worker-src 'none'`, `frame-ancestors 'none'`.
  Обычные JS/CSS загружаются как статические ресурсы; их загрузка не является
  рабочим API. При отсутствующем/ошибочном bootstrap обычный API не используется.
- Набор, отправка, платный поиск, GPT, назначения тренажёра, права, настройки и
  кампании не исполняются. Формы обучения не создают строк в рабочих таблицах.
  При ошибке хранилища или локального обработчика обращения к серверу нет.
- Панель обучения использует существующие страницы/элементы, `tourFind` и обычные
  формы; не создаёт вторую копию карточек, перезвонов, сделок или генератора.
  Контрольные поля/подписи/селекторы находятся в `learning_lessons.json`.
- AveronGPT и исходная экскурсия «Покажи, что где» сохранены. В обычном входе они
  работают прежним способом; в учебном GPT не делает платных запросов. Автотур
  при входе в учебную учётку отключён.

Ограничение: sessionStorage изменяем владельцем браузера. Учебный прогресс нельзя
считать защищённой аттестацией или статистикой директора. Рабочие серверные
права при этом не расширяются. Учебная учётка не является копией всех интеграций:
для разделов вне программ локальных операций может не быть; показывается явное
объяснение, рабочий API вместо отсутствующего учебного не вызывается.

## Запуск отдельного стенда

В обычной SSH-сессии (не systemd):

```bash
cd /tmp/averon-crm-learning-20261104
/opt/callbot-astra/.venv/bin/python -B scripts/learning_demo.py --port 8098
```

На ПК в отдельном PowerShell:

```powershell
ssh -N -L 8098:127.0.0.1:8098 root@201.51.10.59
```

Затем http://127.0.0.1:8098/demo/manager или /demo/director.
Другие сценарии входа: /demo/manager-other, /demo/director-other-company,
/demo/manager-base, /demo/director-base; у /demo/client обучение недоступно.
Каждое открытие ссылки /demo/… считается новым входом и очищает его примеры.
Для проверки продолжения используйте обновление /learning/workspace#… в той же
вкладке, без повторного /demo/…. Стенд слушает только loopback, не читает .env,
не импортирует production make_app и не подключает БД/провайдеров. Все HTTP-записи
на нём заблокированы; учебные сохранения происходят целиком в браузере.

Прогон без сокетов:

```bash
cd /tmp/averon-crm-learning-20261104
CRM_LEARNING_NODE=/root/.local/share/cursor-agent/versions/2026.09.15-d2fe57e/node \
  /opt/callbot-astra/.venv/bin/python -B scripts/check_crm_learning.py
```

На другой машине укажите её путь к Node либо используйте node из PATH.
Прошли 39 Python-тестов, 17 сценариев локального API и 19 сценариев настоящих
контроллеров вкладок в DOM-модели. Проверен синтаксис 33 JS/CJS и 5 Python-файлов.
Проверки запрещают производственные DB/provider-вызовы. Результаты:
`CRM_LEARNING_CHECKS.json`. Прежние iframe-тесты оставлены как история; они не
объявляются проверкой текущего пользовательского пути.

## Оставшийся обязательный browser gate

Попытка запуска `learning_demo.py --port 8098` завершилась OSError: окружение
запрещает bind 127.0.0.1:8098. HTTP-стенд не объявляется успешно запущенным.
Настоящий браузер и визуальная проверка desktop/mobile в этом окружении
недоступны; ограничения не скрываются результатами DOM-модели. До выкладки:

1. Пройти все уроки по обеим ролям в настоящем браузере, включая ошибочные действия.
2. Проверить desktop 1366×900, mobile 390×844, Tab/Shift+Tab/Enter/Esc, модальные
   окна, положение подсказки и видимость рамки, отсутствие перекрытия кнопок.
3. В Network убедиться: при учебных сохранениях только локальный JS, никаких
   HTTP API-записей, lookup, телефонии, GPT или провайдеров. Проверить действие CSP.
4. Reload/пауза/продолжение, черновики, новый вход/выход, смена компании/роли,
   модуль contracts off, модули robot/automations off, прямой адрес чужого урока.
5. На отдельной тестовой БД проверить обычный вход, реальные формы, прежний тур
   и AveronGPT. Production DB для практики и проверки не использовать.

## Выкладка и откат — не выполнялись

1. Пройти browser gate. Сохранить текущую ревизию/рабочие изменения, копии
   затрагиваемых файлов и сверить актуальный production diff.
2. Перенести подготовленные feature/fix/tabs-коммиты в release-ветку без reset и
   переписывания истории; изменения этой ветки зависят от первых двух коммитов.
3. Повторить проверки. Миграций, новых зависимостей и изменений .env нет.
4. Только по отдельной команде пользователя проверить актуальный unit CRM,
   обновить код и перезапустить только CRM; остальные службы не трогать.
5. Откат: git revert конкретного tabs-коммита в release-ветке либо восстановление
   файлов из заранее созданной копии. Это вернёт предыдущую версию обучения;
   рабочие данные не затрагиваются. Не force push и не reset работающего проекта.
6. Для отката всего обучения последовательно отменить его коммиты в обратном
   порядке. Старые sessionStorage-ключи не используются обычной CRM, их удаление
   не требует миграции или очистки рабочих таблиц.

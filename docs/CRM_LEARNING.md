## Что реализовано

«Ещё → Обучение» у менеджера и директора, адрес /#learning. У клиента пункта нет.
Статусы «Не начат», «В процессе», «Пройден». Урок можно продолжить или пройти
заново; повтор очищает только собственную попытку. Прогресс браузерный, отдельно
для учётной записи/компании/роли/версии урока. Общей статистики сотрудников нет.

Пять практических уроков менеджера, пять директора и навигационная экскурсия Д6.
Полная карта «урок → интерфейс → действие → результат → проверка» находится в
[CRM_LEARNING_MAP.md](CRM_LEARNING_MAP.md); её составили до реализации, затем
уточнили по существующим экранам. Кнопки/статусы, отсутствующие в CRM, не выдаются
за рабочие возможности.

В режиме показа используются существующие go/меню, tourFind из helper.js,
CRM-карточки/цвета/кнопки и стабильные data-learning-target. Показ запускается
только вручную. Он не нажимает рабочие кнопки, не отправляет формы и не вызывает
AveronGPT. Отсутствующий элемент не засчитывается: объяснение и переход к практике.
Подсказка находится в потоке страницы, без перекрывающего tooltip. В открытом
native dialog она помещается внутрь dialog, чтобы оставаться доступной с клавиатуры;
карточка не закрывается автоматически с потерей полей. При переходе за её пределы
сотруднику предлагают сначала закрыть её вручную. Закрытие показа оставляет рабочий
экран доступным, восстановление фокуса и Esc предусмотрены. Есть кнопка прокрутки
к выделенному блоку, не выполняющая само действие.

В практике сотрудник действует на вымышленных клиентах, звонках, задачах и сделках.
Проверяется именно действие с нужной записью; «Далее» не завершает практику. Ошибка
даёт конкретную подсказку. Рабочая ситуация всегда видна; дополнительное объяснение
свёрнуто и необязательно. Дата/часовой пояс/условия сохраняются при начале попытки.
«Завтра 15:00 по Москве» переводится в timezone компании, затем остаётся неизменным
при продолжении после полуночи. Отчёт недели и пример Д5 относятся к одному периоду.
У всех сотрудников и периодов разные учебные показатели; случайный seed меняется
при повторе. Д3 проверяет также исходное время и не требует изменять задачу.

Договор М4 формируется как встроенный учебный документ: номер УЧ-..., связь со
сделкой, локальный журнал, флаг «не отправлен». Не используется рабочая нумерация,
DaData, скачивание .docx/PDF и платные вызовы. Отличие от рабочего скачивания,
которое регистрирует договор, объясняется явно.

## Техническая изоляция

- crm/learning.py: только GET-каталог/контекст и защищённый документ практики.
  Роль/компания берутся из существующего Viewer, firm/zone — из существующих функций.
  Client не допускается; чужая роль/компания/отключённый contracts возвращают 403.
- В учебном iframe sandbox="allow-scripts", без allow-same-origin/forms/popups.
  Его ответ имеет CSP connect-src 'none', form-action 'none', default-src 'none',
  script/style-src 'self', frame-ancestors 'self', sandbox allow-scripts.
  В guard сохранение специальных заголовков ограничено ровно /learning/practice.
- Внутри iframe нет app.js/api/work.js/реального генератора договоров/GPT. Движок
  и UI не имеют fetch, XHR, WebSocket, sendBeacon, рабочего API или fallback на него.
  После ошибки либо прямого открытия без родительского контекста рабочего перехода нет.
- Родитель проверяет source окна iframe, nonce, scope, идентификатор попытки,
  версию и revision; сохраняет ограниченный JSON в localStorage. Новая попытка
  и другая вкладка не должны перезаписываться сообщениями старого iframe.
- Браузерный прогресс не является защищённой аттестацией: владелец своего браузера
  способен менять localStorage. Это обучение, не доверенная кадровая статистика.
- Учебных таблиц/фиктивных строк в рабочей БД нет. Миграции не требуются.
  Просмотр реальных экранов в показе делает обычные чтения CRM; практика — локальная.

## Как добавить урок

В crm/learning_lessons.json задайте id/role/module/version/title/result/situation,
показ (page/arg/target/text/result) и шаги с action/expected. Повторно используйте
существующие действия движка/визуализатора. Для нового вида действия добавьте один
обработчик в engine/practice и проверки, страницу программы копировать не нужно.
Повышайте version при несовместимом изменении сценария; старый локальный ключ
не перезаписывается новой версией. Новые реальные контролы размечайте стабильным
атрибутом и сверяйте карту. Схема дат/данных не должна брать реальные записи.

## Запуск изолированного стенда

В обычной SSH-сессии, вне ограничений sandbox (это отдельный процесс, не systemd):

```bash
cd /tmp/averon-crm-learning-20261104
/opt/callbot-astra/.venv/bin/python -B scripts/learning_demo.py --port 8098
```

Стенд слушает только 127.0.0.1, не читает .env, не импортирует production make_app,
не подключает БД/провайдеров. Все POST/PUT/PATCH/DELETE заблокированы. Другие разделы
имеют только ограниченные вымышленные GET-фикстуры для просмотра; это не полноценная
копия всех серверных возможностей CRM. Проверяемые рабочие действия выполняются
именно в изолированном упражнении, а не через эти запретные API.

На ПК откройте отдельный PowerShell:

```powershell
ssh -N -L 8098:127.0.0.1:8098 root@201.51.10.59
```

Пока туннель работает, в браузере:

- http://127.0.0.1:8098/demo/manager — учебный менеджер;
- http://127.0.0.1:8098/demo/director — учебный директор;
- /demo/manager-other — другая учётная запись;
- /demo/director-other-company — другая компания;
- /demo/manager-base и /demo/director-base — без дополнительных модулей;
- /demo/client — клиент, раздел недоступен.

Это намеренно выбираемые тестовые роли без паролей. Стенд не публиковать наружу
и не подставлять в него production DB/ключи. Для завершения — Ctrl+C в терминале
стенда и терминале туннеля. Рабочие службы не затрагиваются.

## Что действительно проверено

```bash
cd /tmp/averon-crm-learning-20261104
/opt/callbot-astra/.venv/bin/python -B scripts/check_crm_learning.py
```

без robot/automations остаются 3 доступных шага. aiohttp-маршруты/guard проверены

## Непройденные проверки и ограничения

Не выполнен реальный браузерный end-to-end и визуальный прогон desktop/mobile:
в среде нет Chromium/Firefox, сеть для загрузки зависимостей недоступна.
Node v24.5.0 найден вне PATH в окружении Cursor: проверен синтаксис всех 27
first-party CRM JS-файлов и повторён тот же UI-набор в native Node VM. Это также
DOM-модель, не настоящий браузер.
Попытка запуска учебного сервера завершилась OSError: could not bind 127.0.0.1:8098
(окружение запрещает создавать локальный сетевой listener). Это не объявляется
успешным запуском HTTP-стенда. Боевая БД не использовалась.

В обычной среде перед выкладкой обязательно проверить:
1. Все уроки через настоящий браузер под обеими ролями, корректный и ошибочный путь.
2. Desktop 1366×900 и mobile 390×844: iframe, формы, длинный текст и подсветка;
   target не перекрывается, закрытие и продолжение работают.
3. Tab/Shift+Tab/Enter/Esc, фокус и поведение при открытом deal-dialog.
4. Реальное применение CSP/sandbox: Network для операций практики не содержит
   POST/PUT/PATCH/DELETE или внешних запросов; после reload/ошибки нет fallback.
5. Прямые адреса d1 у менеджера и m4 без contracts, смена пользователя/компании.
6. Исходные меню, рабочие формы на изолированных данных, AveronGPT и прежний
   «Покажи, что где» в настоящем браузере. Источник helper.js сохранён, но это
   не доказательство отсутствия любых визуальных регрессий.

# Обучение по вкладкам — 4 ноября 2026

Актуальная реализация находится в отдельной копии `/tmp/averon-crm-learning-20261104`,
ветка `feat/crm-learning-guided-programme`. Рабочая CRM не обновлялась. Предыдущие
документы описывают историю; ручной переход «Далее» и контрольные вопросы в новой
программе больше не используются.

## Поведение

До окончания программы в «Обучении» одна кнопка «Пройти обучение»; после паузы —
«Продолжить обучение». Программа последовательно ведёт по вкладкам текущей роли.
Названия — «Урок один. Очередь», «Урок два. Перезвоны» и т. д. Обозначения М/Д
не выводятся. После завершения становятся доступны отдельные уроки по вкладкам.
Число кнопок соответствует доступным вкладкам нынешней программы, а не прежнему
числу сценариев: действия одного сценария, относившиеся к разным вкладкам,
разнесены по вкладкам.

В плавающей карточке — одно действие и короткое пояснение. После рабочего
действия шаг меняется автоматически. Нет тестовых вопросов, полей ответа,
кнопок «Проверить» или «Далее». Внутреннее распознавание нужной записи/действия
сохранено: оно не даёт пропустить действие или засчитать другой объект.
Чтение разбора/истории завершается обычным закрытием окна; понимание текста
не сертифицируется. При переходе в следующую вкладку человек сам нажимает
навигацию CRM; обучение не нажимает кнопки и не сохраняет формы за него.
В скрытом меню сначала выделяется «Ещё», затем нужный пункт.

Крестик приостанавливает текущий шаг. «К программе» возвращает к программе;
пункт «Обучение» в меню также приостанавливает незавершённое действие. Данные,
фильтры и черновики сохраняются в sessionStorage для текущего входа. Новый вход
в учебную учётку очищает примеры и прогресс. Повтор отдельной вкладки использует
чистый снимок её начала, сохраняя нужные предпосылки: созданный ранее перезвон
для переноса, выбранную сделку для договора или недельный отчёт для сотрудника.
Повтор не отменяет завершение основной программы.

## Карта

| Роль | Вкладка | Действия |
|---|---|---|
| Менеджер | Очередь | Нужный клиент → недозвон → история → перезвон с датой, временем и комментарием |
| Менеджер | Перезвоны | Открыть перенос созданной задачи → изменить срок той же задачи |
| Менеджер | Сделки | Открыть сделку → сохранить следующий шаг заметкой → увидеть заметку в истории |
| Менеджер | Договоры, если включены | Учебный документ из сделки → журнал → связанная сделка |
| Менеджер | Звонки | Период 7 дней → нужный звонок → прочитать и закрыть разбор |
| Менеджер | Отчёты | Личный итог по дате → прочитать → вернуться к программе |
| Директор | Сводка | Период 7 дней → Борис Учебный → посмотреть показатели → Звонки |
| Директор | Звонки | Сотрудник/период → нужный звонок → прочитать и закрыть разбор |
| Директор | Перезвоны | Сотрудник → просроченная задача → история → закрыть карточку |
| Директор | Сделки | Зависшие → нужная сделка → этап и история → закрыть карточку |
| Директор | Отчёты | Недельный отчёт нужного периода → прочитать → Сотрудники |
| Директор | Сотрудники | Борис → подтверждающий пример звонка → прочитать и закрыть |
| Директор | Настройки | Открыть Доступы → ознакомиться без изменения настроек |
| Директор | Автоматизации, если включены | Ознакомиться без запуска → следующий раздел |
| Директор | Робот, если включён | Ознакомиться без кампаний/звонков → вернуться к программе |

Маршрут определяется `crm/learning_programme.json`; общий компилятор в
`workspace-model.js` строит последовательность и подписи. Старый реестр
`learning_lessons.json` сохранён для совместимости старых попыток и автономных
проверок движка, но его вопросы и идентификаторы не выводятся в новом интерфейсе.
Состав модулей входит в версию программы: смена доступных вкладок не засчитывает
устаревшее завершение как прохождение новой программы.

## Проверки и ограничения

Запуск без БД, сети, моделей и рабочих настроек:

```bash
cd /tmp/averon-crm-learning-20261104
CRM_LEARNING_NODE=/root/.local/share/cursor-agent/versions/2026.09.15-d2fe57e/node /opt/callbot-astra/.venv/bin/python -B scripts/check_crm_learning.py
```

Результаты записаны в `CRM_LEARNING_GUIDED_CHECKS.json`. Автоматические проверки
выполняют настоящие JS-контроллеры и формы CRM через адаптер DOM. Проверены обе
программы целиком, отдельный повтор каждой доступной вкладки дважды, ошибочные
действия, пауза/возврат/обновление, черновики, включённые и выключенные модули,
блокировка отдельных уроков до завершения, разделение учёток и отсутствие
сетевого fallback. Старый транспорт обычного входа проверяется отдельно.
Геометрические проверки используют вымышленные прямоугольники, не браузер.

Реальный Chromium/Playwright отсутствует. Браузерный скрипт
`scripts/check_crm_learning_browser.cjs` обновлён под автоматические переходы,
но его выполнение заканчивается NOT RUN с кодом 2. Настоящие скриншоты,
визуальная проверка светлой/тёмной темы и системной мобильной клавиатуры здесь
не выполнены. Нельзя считать снимки DOM доказательством реальной вёрстки.
Подключение к TCP-стенду из текущей инструментальной среды также недоступно.

## Открыть тестовый стенд

На ПК в PowerShell:

```powershell
ssh -L 8098:127.0.0.1:8098 root@201.51.10.59
```

После входа, уже в серверной оболочке (без пробелов внутри `/opt`):

```bash
cd /tmp/averon-crm-learning-20261104
/opt/callbot-astra/.venv/bin/python -B scripts/learning_demo.py --port 8098
```

Если прежний тестовый процесс уже занимает порт, в его терминале сначала
Ctrl+C, затем повторить запуск. Для нового Python-контекста программы нужен
перезапуск именно тестового скрипта; службы рабочей CRM не трогать.
Оставить SSH-окно открытым. На ПК:

- http://127.0.0.1:8098/demo/manager
- http://127.0.0.1:8098/demo/director

Маршруты выдают вымышленные роли без производственных учётных данных. После
нового входа выполнить Ctrl+F5. Обновление самой `/learning/workspace` сохраняет
попытку; повторный `/demo/...` начинает чистый вход. Пароли и база не нужны.

## Выкладка и откат

Выкладка не выполнялась. До неё нужна браузерная приёмка на тестовом стенде.
Новых зависимостей/миграций нет. Переносить нужно всю согласованную ветку
обучения, включая предшествующие изолированные коммиты, а не только последний
коммит поверх старой production-версии. Зафиксировать текущую ревизию и копии
затрагиваемых файлов; затем после отдельного разрешения обновить только CRM.

Откат на предыдущий интерфейс стенда — вернуть ревизию
`b19b3c10285336d44bcbe02dca5bdbef883d0f53` в отдельной копии. Не выполнять reset
или checkout в рабочем каталоге. Данные обучения локальные, рабочая БД не
меняется; удалять рабочие записи при откате не требуется.

# Основа личного плана дня

Маршруты подключаются только при `CRM_PERSONAL_DAY_ENABLED=1`; по умолчанию флаг выключен. Миграция `059_crm_personal_day.sql` включена в `scripts/crm_setup.sh` после 057. Миграция 058 и маршруты Google в этот пилот не включены. Существующий допуск `CRM_PERSONAL_PILOT_TELEGRAM_IDS`, активный сотрудник и действующее персональное приглашение обязательны; без списка пилота раздел закрыт. Личный профиль и его часовой пояс должны быть заполнены через существующий API.

`GET /api/personal/day?date=2027-01-02` возвращает дату в часовом поясе профиля и категории `today`, `overdue`, `blocked`, `unscheduled`. Без даты используется сегодняшний день в часовом поясе профиля. Личные задачи выбираются только владельца, командные — только назначенные ему в его компании; завершённые и отменённые исключаются. Препятствие имеет приоритет при классификации, затем просроченный срок, затем срок или запланированный день. Будущие и отложенные задачи в выдачу дня не включаются. Сроки преобразуются в часовой пояс профиля до сравнения с датой. Ссылка на сделку повторно проверяется по действующим правам. Пока поставщик календаря не подключён, `appointments` равен `null`, `appointments_status` — `not_connected`; это не означает отсутствие встреч.

`GET /api/personal/day/settings` возвращает настройки и часовой пояс профиля. Изменение выполняется только самим владельцем через `PUT /api/personal/day/settings`, с `X-CRM: 1`, пример:

```json
{"version":0,"work_start":"09:00","work_end":"18:00","priorities":["Подготовить предложение"],"morning_time":"08:30","evening_time":"18:30"}
```

Все поля обязательны; время утреннего или вечернего обзора может быть `null`. Нулевая версия означает отсутствие сохранённых настроек; каждый следующий запрос передаёт актуальную версию, при конфликте сервер возвращает 409. Приоритетов не более пяти. Время — местное по часовому поясу профиля. Эти настройки пока ничего не отправляют и не запускают, расписание и календарь не реализованы.

Проверка: в специально созданной локальной БД `callbot_methodology_test_personal_day` задать `PERSONAL_DAY_TEST_DSN` и запустить `python -m unittest tests.test_personal_day -v`. Интеграционный тест удаляет и создаёт схему `public` в указанной БД; никогда не указывайте рабочую БД. Без DSN выполняются только проверки правил, интеграционные пропускаются.

Для будущего подключения календаря `day_bounds_utc(date, ZoneInfo)` возвращает начало и конец местного дня как полуоткрытый интервал UTC с учётом переходов времени. Поставщик пока не вызывается.

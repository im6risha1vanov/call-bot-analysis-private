## Пути и сообщения

| Путь | Итоговое поведение |
|---|---|
| Mango → `analyze_call` | Сохраняет исходную оценку и краткий внутренний результат; фиксирует запуск, ставит внутренние проверки и единственную публикацию |
| `evaluate_course` | Сохраняет независимые критерии курса; для звонков самостоятельно сообщений не отправляет |
| `automatic_combined_call` | Сохраняет независимый результат с применимостью и проверенными цитатами; самостоятельно сообщений не отправляет |
| `publish_call_report` | Ожидает дополнительные результаты, готовит один общий текст и доставляет по отдельному ключу каждому получателю |
| `/review <номер>` | Явное открытие сохранённого итога, без платного анализа и без изменения истории |
| `uv:e:<run>` | Обзор строго того запуска; локальная генерация из снимков с кэшем и блокировкой строки |
| Старый `detail:astra:<call>` | Проверяет пользователя нажатия и открывает обзор сохранённого запуска; для истории без снимка создаёт совместимое представление без нового платного анализа |
| Старые `av:*` | Сохраняют доступ к уже готовым историческим дополнительным вариантам; новых автоматических сообщений не создают |
| Менеджерский дайджест | Статистика сохранена; для звонков с новым запуском не добавляет старый фрагмент краткого разбора |
| Агент РОПа | Вопросы и сводки продолжают работать отдельно от обычного сообщения звонка |
| Тренажёр | Сессии, голос/текст, смешанная короткая серия, оценка и очередь обратной связи не изменены |
| `/compare_analysis` | Явный слепой эксперимент: отдельные А/Б, голосование и раскрытие сохраняются |
| `/combined_analysis` | Явный пробный эксперимент над выбранными звонками сохраняется |

Внешний ручной аудиофайл в основном боте по-прежнему не принимается. Это
не новый способ загрузки записи. `/review` открывает результат, а не начинает
новый оплачиваемый анализ. Новый явно поставленный запуск анализа с другим
идентификатором задачи имеет отдельный снимок и отдельный ключ доставки.

## Оценка и формат

Активная исходная шкала определяет числовой балл. В текущем `shadow` новая
методика остаётся дополнительной; её числовая шкала не откалибрована.
Баллы не складываются и не выбирается более высокий. Исходные критерии
показываются в обзоре отдельно от дополнительных. Коммерческий результат
отделён от качества разговора. Неприменимые навыки не объявляются провалами
дополнительной шкалы. Контекстные ограничения основной шкалы и расхождения
не скрываются; спорные наблюдения исключаются из общего текста.

Для основного текста берутся максимум два сильных действия и три упущения.
Цитаты должны буквально находиться в закреплённой транскрипции; выдуманные
таймкоды не выводятся. Дубликаты критериев и реплик удаляются. Объекты не
превращаются в пользовательский JSON. Рекомендации берутся из сохранённого
разбора этого разговора и подписываются как пример другой реплики.
По уточнённому запросу владельца номер клиента показывается полностью в новых
снимках. Старые снимки сохраняют прежнее представление. HTML
экранируется после компоновки, ограничения проверяются в единицах UTF-16.

Целевой объём — компактный содержательный текст. При недостатке данных
пункты не дополняются искусственно. Длинные пояснения остаются в обзоре.
Обзор строится по сохранённым критериям, причинам, репликам, возражениям,
договорённостям и рекомендациям. Дополнительный LLM ради повторного изложения
готовых результатов не вызывается. Если нет части данных, это отмечается.

## Состояние, права, доставка

Миграция `005_unified_call_reports.sql` добавляет две таблицы:

- `call_report_runs`: неизменяемый снимок для конкретного звонка и запуска,
  конфигурация, версии источников, готовый общий текст и кэш обзора;
- `call_report_delivery`: ключ `(call_id, run_id, recipient)`, состояния
  `pending/sending/sent/uncertain/forbidden`, идентификатор сообщения и попытки.

Повтор одной задачи повторно использует её `task:<id>`. В будущем новый
явный анализ — новая задача, следовательно другой запуск. Старые уже
рассыланные задачи после обновления не превращаются в историческую рассылку.
Полная версия старых настроек, отсутствующая в исторической БД, не
восстанавливается догадкой: модель/промт отмечены неизвестными. Для новых
вычислений фиксируются модель, хеш промта, веса и правила вердикта.

Снимок готового итога не обновляется после смены режима или позднего
поступления дополнительного результата. Ожидание — до 30 минут от создания
снимка. После этого публикация использует доступные данные и показывает
ограничение. Это ожидание не считается превышением расходного лимита.

Авторизация основана на `callback.from_user`, существующем `Actor`,
`client_id`, добавочном менеджера и повторном `get_call`. Личный чат обязателен.
Просмотр старого снимка также проверяет текущую принадлежность звонка.
Одновременные клики блокируются строкой снимка. Ошибка локальной генерации
не меняет обычный итог; следующий клик повторяет только недостающий обзор.
Длинный обзор выдаётся пронумерованными частями или UTF-8 файлом, с возвратом.

Bot API Telegram не обеспечивает атомарную транзакцию с PostgreSQL и не
принимает наш ключ идемпотентности. Поэтому при таймауте или аварии между
отправкой и записью квитанции система оставляет `uncertain`, а не отправляет
вслепую ещё раз. Это предотвращает дубль, но может оставить недоставленное
сообщение. Известные отказы Telegram повторяются только недоставленным
получателям. Запрет доставки фиксируется отдельно; просмотр `/review`
остаётся явным способом получить сохранённый итог. Надзор видит состояния
доставки отдельно от статуса задачи `done`; не объявляет очередь пустой при
новых/исполняемых задачах или неподтверждённой доставке.

## Уточнение оформления и явный новый разбор

Новый формат `combined_style_20261004_v2` использует разделы прежнего
«Объединённого разбора» с эмодзи и понятным знаком действующего вердикта.
Номер звонка и служебные счётчики из шапки/текста убраны. Полный номер
сохраняется при новом захвате снимка; старые записи не восстанавливаются
догадкой и не редактируются. Балл и знак остаются по исходной методике.

`call_report_generation` хранит отдельно два этапа явного повторного анализа:
исходную оценку и предметный объединённый разбор. Для них закреплены промты,
параметры, версия пакета, каталог и конфигурация, сохранены ответы и расход.
Такой запрос создаёт новый `call_report_runs`, не меняя `astra_analysis` и
старых отчётов. Конкурентные запуски защищены блокировками; повтор готового
запроса не вызывает модель; неизвестный исход не оплачивается снова вслепую.
Подробности сохраняют именно новые результаты.

Сохранение балла не означает, что предметный профиль стал основной числовой
шкалой. Инструкция РОПу объясняет 12 критериев и формулу, точные пороги
ключевых провалов 3/2, приоритет встречи/предложения/контакта в ✅, четыре
состояния предметных критериев, уверенность профиля 75% и отсутствие
утверждённых коммерческих условий на дату проверки.

# Разбор звонка по результату (call_review_v2)

Решения владельца от 07.10.2026: балла и 12 критериев нет; вопрос один — был ли
результат (сделка, встреча, перезвон в конкретный день, КП, контакт ЛПР), и если
нет, где он потерян и что надо было сказать. Промт откалиброван на 265 звонках
14.09–07.10.

## Как устроено

| Шаг | Где |
|---|---|
| Один запрос к модели вместо оценки и короткого отчёта | `review/engine.py`, промт `review/prompt.md` |
| Проверка: цитата дословно в расшифровке, у того же спикера, ±5 с от таймкода; результат засчитывается только с подтверждающей репликой | `engine.validate` |
| Если вывод модели не прошёл проверку, текст собирается из проверенных полей | `render.from_fields` |
| Хранение | таблица `call_reviews` (`migrations/008_call_reviews.sql`) |
| Сразу менеджеру: без результата, но шанс был; сразу РОПу и владельцу: только «горячие» потери | `store.deliver_now` |
| В `clients.digest_time`: менеджеру итог дня, удачные моменты, одна вещь на завтра, договорённости на завтра; РОПу цифры по менеджерам и список потерь с кнопками | `astra_worker.send_review_digests` |
| Кнопка «Подробнее» (`rv:d:<call_id>`), права как у разборов: менеджер видит только свои | `review/ui.py` |
| Кнопка «Потренировать» (`rv:t:<call_id>`) у менеджера при потере: назначение в тренажёр с темой `review:<call_id>`, клиент и момент берутся из разбора | `store.train_assignment`, `training_simulator.review_scenario` |
| Перезвоны: задача из договорённости с датой; в 9:00 по будням менеджеру список на сегодня и просроченные, за 30 минут до перезвона со временем — напоминание; кнопки «Выполнено / Перенести / Отменить» (`cb:`); новый разговор с тем же номером закрывает открытую задачу | `review/callbacks.py`, таблица `callback_tasks` |
| Google-таблица: листы «Звонки» (60 дней) и «Перезвоны», перезапись из базы раз в 10 минут; правки в таблице не читаются | `review/sheets.py` |

Не разбираются (сообщения нет, `level` пустой): автоответчики и обрывы,
не продажи, звонки не про продукты Averon (списание долгов, банкротство).

`astra_analysis` по-прежнему заполняется (`level`: ✅ результат, ❌ потеря с
шансом, ⚠️ без шанса), поэтому статистика и агент РОПа продолжают работать.
Баллов нет, разбивка по критериям для новых звонков пустая.

## Включение

1. Применить `migrations/008_call_reviews.sql` и `migrations/009_callback_tasks.sql`;
   `pip install -r requirements.txt` (добавлены `google-auth`, `requests`).
2. `CALL_REVIEW_MODE=v2` в `.env`, перезапустить queue-runner (разбор и
   отправка), основной бот (кнопки) и Mango-worker (сводки, перезвоны, таблица).
3. Время вечерней сводки — `clients.digest_time` (по решению владельца 19:00).
4. Тренажёр: `TRAIN_BOT_USERNAME` в `.env` основного бота (без него кнопки
   «Потренировать» нет), перезапустить бот-тренажёр.
5. Google-таблица (необязательно): создать сервисный аккаунт Google с Sheets API,
   положить JSON-ключ на сервер, дать его e-mail доступ «Редактор» к таблице;
   в `.env` worker: `GOOGLE_SERVICE_ACCOUNT_FILE=/путь/к/key.json`,
   `GOOGLE_SHEET_ID=<id из ссылки на таблицу>`.

Без переменной работает прежний конвейер без изменений. Откат: убрать
переменную и перезапустить те же службы; таблица `call_reviews` остаётся.

## Пока не сделано

- Утренний, недельный и месячный дайджесты агента РОПа ещё не знают категорий
  потерь (опираются на ✅/⚠️/❌).
- Разделение спикеров при распознавании: в 95 из 265 звонков расшифровка идёт
  одной меткой; промт и проверка это учитывают, но лучше распознавать по
  каналам записи.
